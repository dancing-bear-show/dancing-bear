# Workflow Fragment and Context File Guide

## When loaded

Load this guide when the diff contains `.llm/` context files (CONTEXT.md,
DOMAIN_MAP.md, PATTERNS.md, FLOWS.yaml, AGENTIC.md, AGENTS_CAPSULE.yaml),
agent definitions under `.claude/agents/`, or generated output files under
`.llm/` that are regenerated by `./bin/llm derive-all`.

Fragment/include concerns are split into this file; general flow correctness
concerns live in `workflow.md`.

## Concerns

### generated-file-hand-edited
- **severity**: major
- **check**: Verify that generated `.llm/` files (those with `.generated.` in
  their name, or documented as derived outputs) are not hand-edited. Hand edits
  are silently overwritten on the next `./bin/llm derive-all` run.
- **triggers**: Diff modifies `.llm/FLOWS.generated.yaml`, `.llm/AGENTIC.md`,
  `.llm/DOMAIN_MAP.md`, or other files documented as generated outputs when no
  corresponding change to the generator source is included in the same PR.
- **example**: PR directly edits `.llm/FLOWS.generated.yaml` to add a flow entry —
  the next `./bin/llm derive-all` run overwrites the edit. Fix: add the flow to
  `.llm/FLOWS.yaml` (the canonical source) and regenerate.

### context-file-param-not-wired
- **severity**: major
- **check**: Verify that `{param}` placeholders in `.llm/FLOWS.yaml` flow
  commands are either substituted at invocation or documented as literal shell
  variables that callers must export. Unsubstituted placeholders produce broken
  CLI invocations.
- **triggers**: `cmd` or `steps` values in `.llm/FLOWS.yaml` containing `{...}`
  placeholders; flow descriptions that do not explain how the placeholder is
  resolved at call time.
- **example**: `cmd: ./bin/calendar --profile {profile} outlook verify-from-config`
  — if `{profile}` is not substituted before the command runs, the shell sees the
  literal string `{profile}` and the CLI fails with an unrecognized profile. Fix:
  document the substitution mechanism or use a concrete default value.

### cross-context-constant-drift
- **severity**: major
- **check**: Verify that logical constants shared across `.llm/` context files
  (CLI entry point names, profile names, output path conventions) are consistent.
  A value documented one way in CONTEXT.md and differently in FLOWS.yaml produces
  confusion and incorrect agent invocations.
- **triggers**: CLI entry point names, profile key names, or output path patterns
  that appear in more than one `.llm/` file with different spellings or values;
  flow steps that use a profile name not matching the credential key format
  documented in CONTEXT.md or CLAUDE.md.
- **example**: CONTEXT.md documents the Gmail profile key as `gmail_personal` but
  a FLOWS.yaml entry uses `gmail-personal` (hyphenated) — agents following the flow
  get a credential lookup failure. Fix: canonicalize to one form across all context
  files.

### agents-capsule-role-stale
- **severity**: minor
- **check**: Verify that `.llm/AGENTS_CAPSULE.yaml` and the agent definitions
  table in CLAUDE.md reflect the same set of agent roles with consistent model
  assignments. A stale capsule causes agents reading it to spawn teammates with
  wrong model or capability assumptions.
- **triggers**: A PR adds a new agent role to CLAUDE.md's agent table without
  updating `.llm/AGENTS_CAPSULE.yaml`; or updates `.llm/AGENTS_CAPSULE.yaml`
  without the corresponding CLAUDE.md table change; model name changes in one
  location but not the other.
- **example**: CLAUDE.md documents `tester: Sonnet` but `.llm/AGENTS_CAPSULE.yaml`
  still shows `tester: Haiku` — agents reading the capsule spawn an under-powered
  model for test writing. Fix: update both files in the same commit.

### familiarize-flow-stale
- **severity**: minor
- **check**: Verify that `.llm/familiarize.yaml` (or `familiarize.json`) includes
  all current primary `bin/` entry points in its reading-order and context-loading
  list. Stale familiarization flows cause new sessions to miss recently added CLIs.
- **triggers**: A PR adds a new `bin/` entry point or domain module without updating
  the familiarization manifest; `.llm/familiarize.yaml` lists a `bin/` path that no
  longer exists.
- **example**: PR adds `bin/desk-assistant` but `.llm/familiarize.yaml` still lists
  only `bin/mail-assistant`, `bin/calendar-assistant`, and `bin/schedule-assistant`
  for schema preloading — new sessions do not discover the desk CLI. Fix: add the
  new entry point to the familiarization manifest in the same PR.

### skill-used-by-list-stale
- **severity**: minor
- **check**: Verify that skill or agent definition files that list their callers
  (e.g. in a header comment or `used_by` field) include every workflow or flow that
  references them. A stale list understates blast radius when making breaking changes.
- **triggers**: Agent definition YAML files or SKILL.md files with a `used_by:`,
  `# Used by:`, or `callers:` annotation; a PR adds a new reference to an existing
  agent definition without updating the definition's caller list.
- **example**: An agent definition header says `# Used by: code-review, pr-review` but
  this PR wires the agent into a third workflow — the header now understates blast
  radius. Fix: update the `Used by:` annotation in the same commit that adds the
  new reference.
